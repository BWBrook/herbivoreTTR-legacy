### 4) Iteration and fixes performed during review

Two correctness issues were detected and fixed during WP-3.1 hardening:

1. GUI startup fallback bug:
- `portal/gui/app.R` previously used `%||%` without defining it.
- Replaced with explicit, dependency-free path resolution helper (`resolve_app_start_dir()`).

2. Plan-default merge bug for indexed sensitivity lists:
- Default/user recursive merge treated unnamed parameter lists as keyed objects, which could erase user sensitivity parameters.
- `portal_merge_defaults_v1()` was updated to replace unnamed/indexed lists atomically.
- Regression coverage added in `tests/testthat/test_portal_plan_v1.R`.

3. Report format handling hardening:
- HTML render path now calls Quarto with explicit `--to html` so HTML-only requests do not implicitly emit PDF side-products.
- Regression coverage added in `tests/testthat/test_portal_runner_v1.R`.
