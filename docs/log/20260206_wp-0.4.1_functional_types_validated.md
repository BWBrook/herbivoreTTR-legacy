# WP-0.4.1 — Functional types validated (grazer vs browser)

Date: 2026-02-06  
WP: `WP-0.4.1`  
Author: Codex autonomous run

## Summary

Implemented explicit grazer/browser vegetation-type preference multipliers in tastiness scoring and added a controlled functional-type scenario artefact generator.

Result: in a fixed-seed grass+tree control scenario, grazers and browsers now show reproducibly distinct diet composition, and browser intake from unreachable tall woody plants remains zero.

## Implementation notes

- Added functional-type preference constants in `CONSTANTS`:
  - `GRAZER_GRASS_PREF`, `GRAZER_WOODY_PREF`
  - `BROWSER_GRASS_PREF`, `BROWSER_WOODY_PREF`
- Added internal helpers:
  - `functional_type_preference_multiplier()`
  - `functional_type_label()`
- Updated `calc_plant_tastiness()` to apply vegetation preference multipliers by `herb_type`.
- Added controlled scenario helper:
  - `run_functional_type_scenario()` writing artefacts to `artefacts/canonical_runs/functional_types_v0/`
- Added targets smoke artefact target:
  - `functional_type_bundle_files`

### 3) Interpretation

Definition of “distinct” used for WP-0.4.1:
- grazer grass share is materially higher than browser grass share;
- browser tree share is materially higher than grazer tree share;
- browser does not consume unreachable tall woody plants.

This satisfies the controlled-scenario acceptance criteria for measurable grazer/browser split and browse-height/reach enforcement.
